# Multi-Agent Architecture for ns-3 Simulations

## Overview
The system has been transformed from a ReAct-style single agent to a hierarchical multi-agent architecture with specialized agents working together to create, test, and validate ns-3 simulations.

## Agent Hierarchy

### 1. Manager/Orchestrator Agent
**Role:** High-level planning and coordination

**Responsibilities:**
- Breaks down user queries into structured sub-tasks (DAG plan)
- Creates tasks with dependencies: topology, protocol, traffic, data_collection, validation
- Tracks progress and coordinates other agents
- Decides when to move to next task or complete the workflow

**Output:** Structured plan with task_id, description, type, dependencies, and status

### 2. Repository Custodian (RAG Specialist)
**Role:** Documentation retrieval expert

**Responsibilities:**
- Searches the hierarchical knowledge base (3 levels)
- Does NOT write code, only provides documentation context
- Reduces hallucinations by retrieving correct API signatures

**3-Level Hierarchical Search:**
- **Level 1 (Summary):** High-level guides and tutorials
- **Level 2 (API):** Specific class references and method signatures
- **Level 3 (Code Examples):** Verified snippets from ns-3 examples

**Output:** Relevant documentation for the current task

### 3. Developer (Coder) Agent
**Role:** Code generation

**Responsibilities:**
- Writes ns-3 C++ simulation code
- Uses documentation from Custodian
- Incorporates feedback from QA and Reflection agents
- Follows ns-3 best practices (smart pointers, logging, metrics output)

**Output:** Complete C++ simulation code

### 4. QA Engineer (Tester) Agent
**Role:** Testing and validation

**Responsibilities:**
- Executes simulation code using ns3_tool
- Analyzes output for errors (compilation, runtime, logic)
- Generates structured bug reports
- Extracts and validates metrics (packet loss, delay, throughput)

**Output:** Test results, metrics, or detailed bug reports

### 5. Self-Reflection Agent
**Role:** Code quality critic

**Responsibilities:**
- Reviews code BEFORE testing
- Checks smart pointer usage, event scheduling, memory management
- Verifies ns-3 API correctness
- Provides constructive feedback with specific suggestions

**Output:** Code quality assessment and improvement suggestions

## Workflow

```
User Query
    ↓
Manager (creates plan)
    ↓
Custodian (retrieves docs) ← Level 1/2/3 hierarchical search
    ↓
Developer (writes code) ← uses docs + previous feedback
    ↓
Reflection (reviews code) → feedback loop to Developer if issues
    ↓
QA Engineer (tests code) → bug reports back to Developer if fails
    ↓
Manager (next task or complete)
    ↓
Final Answer
```

## Key Features

### 1. Task Decomposition
The Manager breaks complex queries into logical sub-tasks with dependencies:
- Topology setup
- Protocol configuration
- Traffic patterns
- Data collection
- Validation

### 2. Iterative Refinement
- Developer can iterate up to 5 times based on feedback
- Reflection agent catches issues before expensive testing
- QA provides structured bug reports, not raw logs

### 3. Hierarchical RAG
The knowledge base is searched at different levels:
- **Summary level:** Broad concepts and tutorials
- **API level:** Specific class/method documentation
- **Code example level:** Working code from ns-3 repository

### 4. Separation of Concerns
Each agent has a single, well-defined responsibility:
- Custodian only retrieves, never writes code
- Developer only writes code, doesn't test
- QA only tests, doesn't fix
- Reflection only critiques, doesn't implement

## State Management

The `AgentState` tracks:
- **Plan:** List of SubTasks with dependencies and status
- **RAG Context:** Documentation retrieved by Custodian
- **Code:** Generated by Developer (with iteration count)
- **Test Results:** Metrics and bug reports from QA
- **Reflection Feedback:** Quality issues and suggestions
- **Messages:** Communication log between agents

## Tool Integration

All existing tools are preserved:
- `search_knowledge_base` - Enhanced with 3-level hierarchical search
- `ns3_tool` - Used by QA for simulation execution
- `read_ns3_example` - Used by Custodian for code examples
- `list_ns3_examples` - Used by Custodian to discover examples
- `search` - Web search (available to all)
- `python_repl` - Python execution (available to all)

## Benefits

1. **Reduced Hallucinations:** Custodian retrieves correct API docs before coding
2. **Better Code Quality:** Reflection catches issues early
3. **Structured Debugging:** QA provides specific bug reports, not raw output
4. **Scalability:** Each agent can be enhanced independently
5. **Transparency:** Clear communication log shows agent coordination
6. **Robustness:** Multiple feedback loops ensure correctness
